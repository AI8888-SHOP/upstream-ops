# v0.0.54 — 历史费用与利润重算

## 新增与修复

- 保存、删除或同步模型价格后，历史参考成本、预估收入和参考利润一起重算，不再被原先为 0 或正数的旧结算金额锁住。
- 按当时实际上游模型、原始用量和虚拟缓存 Token 计算销售基数，复用上下文阶梯、5m/1h 缓存价格；保留原源分组倍率，报表使用网关组当前卖出倍率。
- 首次升级后自动安排一次可恢复的后台历史补算，每批最多 200 行；也可在“价格覆盖”点击“重算历史费用与利润”。
- Token 计费且全部真实用量、已记录费用均为 0 的请求，报表按 0 元计入并单独显示“零用量异常”，不再因此阻塞利润。
- 有实际用量但缺模型价格的记录仍待计价；明确配置免费与缺少价格分开处理。删除唯一可用单价后，不使用过时的历史收入冒充新价。
- 失败、重试及并发尝试的成本继续保留，只有成功交付的最终尝试计收入；缺用量但已记录费用的异常记录不会被抹零。
- 增加历史零/正结算更新、重复重算、升级补算幂等、五层日报汇总及 PostgreSQL 结算竞态回归覆盖。

## 升级说明

- 历史重算改变的是使用记录与报表的参考金额；不修改原始 Token、实际 Key 扣款、余额、额度或结算凭据，不追扣差价。
- 补算期间可能暂时混合新旧价格。请在“价格覆盖”确认后台任务完成后刷新每日报表；价格仍缺失的模型需要配置有效单价。
- 零用量按 0 元是报表约定，不代表上游一定没有扣款；报表是参考毛利，不是实际账务对账单。
- 建议升级前备份数据库。编译和完整测试由 GitHub Actions 执行，本机不编译；本次发布不自动修改或部署到 2026v6。

详见 `docs/model-pricing.md` 和 `docs/daily-report.md`。
