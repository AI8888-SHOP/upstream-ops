# v0.0.53 — 多层 sub2api 合成首响应

## 新增与修复

- 网关组编辑新增独立的「合成首响应（多层 sub2api 兼容）」开关，解决第一层 sub2api 已记录 semantic 首字、却缓冲空 reasoning 事件，导致第二层仍需等待真实输出的问题。
- 多层模式在 Responses 生命周期前缀后发送单个推理摘要空格 delta，使已核对的 sub2api 输出判定逻辑开始转发；无需修改下游源码。
- 完整维护合成 reasoning 项的开始、摘要、结束及终端输出，保留真实回答、工具参数、模型审计和上游用量。后续请求仅清除专用命名空间下的精确合成项，不删除真实或未知推理内容。
- 增加双层 HTTP 缓冲转发、真实首字预算、开关依赖、快速上游不改写、校验拒绝换源、最终失败及异常终端不计费等回归覆盖。

## 启用方式与限制

- 新开关默认关闭，升级不会自动改变现有网关组行为。需要同时开启首包保活、sub2api 首字统计兼容和多层合成首响应，沿用原随机毫秒区间。
- 仅适用于入站 `/v1/responses` 的流式文本请求，且明确 `store:false`、无会话续接及后台模式；不满足条件时使用普通 SSE 注释保活。
- 合成空格会让下游认为已开始输出，解除其首输出超时保护，并可能影响下游自己的失败重试与换源。本网关仍按真实上游输出计算 TTFT、执行真实首字预算、响应校验和结算；该功能不提高真实模型生成速度。
- 响应使用网关生成的 ID，不能用于 `previous_response_id` 续接或向上游按 ID 查询响应；消费者不能假定 `output[0]` 是正文。
- 不保证任意代理版本、缓冲配置或协议转换路径均有相同表现；建议先在单个网关组验证。最终失败仍返回流内错误，不伪造成功或 Token 用量。
