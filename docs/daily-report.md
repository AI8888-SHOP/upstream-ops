# 每日报表

入口：顶部导航“每日报表”，地址 `/daily-report`。

- 默认按 Asia/Shanghai（北京时间）自然日显示今日、昨日；可指定日期，查看所选日和前一日，也可切换 UTC 或浏览器本地时区。
- 两张汇总卡显示上游参考消费、去重请求数、成功交付数、上游尝试次数、Token 和真实缓存命中率，并标出消费最高渠道、该渠道消费最高源分组及模型。
- 渠道排行可按消费或请求次数排序；渠道内展开源分组，再展开每个请求模型。消费最多模型和请求最多模型分别统计，渠道模型统计横跨该渠道所有源分组。
- 支持搜索渠道、源分组、请求模型。没有流量的日期显示空状态；没有有效输入 Token 样本时，缓存命中率显示“—”，而非伪造 0%。

## 统计口径

- 消费是使用日志的 `actual_cost`（USD 上游参考成本）合计，包括失败、拒绝、重试和并发尝试中已记录的成本。它不是上游站点发票或实际扣账，也不是用户网关 Key 的 `billed_cost`。上游未报告用量/成本的请求无法据此推断实际扣款。
- 价格覆盖的历史重算更新参考成本后，刷新日报读取更新后的金额；日报不修改 Key 已结算金额或余额。
- 请求数按各层级内 `request_id` 去重，成功交付按 `winner` 去重。一个请求跨多个渠道/源分组重试，会同时出现在相关分项，因此分项请求数不可直接相加；成本和 Token 是所有 attempt 的可加总量。
- Token = 新鲜输入 + 输出 + 真实缓存写入 + 真实缓存读取。虚拟缓存是结算重分类，不再加一次 Token。
- 真实缓存命中率 = 成功 attempt 的缓存读取 Token /（新鲜输入 + 缓存写入 + 缓存读取），排除虚拟缓存和失败 attempt，沿用使用记录统计口径。
- 来源身份是“来源类型 + 渠道 ID”。源分组再按源组 ID 区分，ID 仅在本渠道内唯一；历史无 ID 时用快照名称。已知 ID 的组改名不拆成两组，按范围内最后一条日志显示名称。删除的直连渠道保留日志名称快照。

## 实现

`GET /api/gateway/usage/daily-report?date=2026-10-21&timezone=Asia%2FShanghai`

日期省略时取所选时区当前日，时区省略时取 Asia/Shanghai。日期和时区非法返回 400；接口沿用管理端鉴权。

数据库只读取所选自然日及前一日时间范围，通过一个 CTE 和五层聚合生成日、渠道、渠道模型、源分组、源分组模型结果；没有将原始使用记录加载到应用内存，也没有按渠道 N+1 查询。名称用最多三个固定批量查询补全。前端不自动高频轮询日报，点击刷新才重新汇总，避免后台重复扫描大日志。

回归覆盖北京时间跨日、DST 日界限、已知源组改名、相同源组 ID 跨站点隔离、直连/监控 ID 冲突、失败成本、真实缓存、跨组请求去重、删除渠道名称、金额重算更新及 PostgreSQL 聚合。
