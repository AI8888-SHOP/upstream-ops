# 每日报表

入口：顶部导航“每日报表”，地址 `/daily-report`。

- 默认按 Asia/Shanghai（北京时间）自然日显示今日、昨日；可指定日期，查看所选日和前一日，也可切换 UTC 或浏览器本地时区。
- 两张汇总卡显示上游参考消费、预估收入、参考利润、利润率、去重请求数、成功交付数、上游尝试次数、Token 和真实缓存命中率，并标出消费最高渠道、该渠道消费最高源分组及模型。
- 渠道排行可按消费、利润或请求次数排序；利润排序将未计价项放在最后。渠道内展开源分组，再展开每个请求模型，均可查看收入、利润及利润率。消费最多模型和请求最多模型分别统计，渠道模型统计横跨该渠道所有源分组。
- 今日、昨日、渠道、源分组和模型利润旁单独展示“零用量异常 N 笔”，与“待计价”分开；异常按成功交付的 Request ID 去重，不重复统计失败或未胜出的尝试。
- 支持搜索渠道、源分组、请求模型。没有流量的日期显示空状态；没有有效输入 Token 样本时，缓存命中率显示“—”，而非伪造 0%。

## 统计口径

- 消费是使用日志的 `actual_cost`（USD 上游参考成本）合计，包括失败、拒绝、重试和并发尝试中已记录的成本。它不是上游站点发票或实际扣账，也不是用户网关 Key 的 `billed_cost`。上游未报告用量/成本的请求无法据此推断实际扣款。
- 价格覆盖的历史重算同时更新参考成本和收入基数，刷新日报读取更新后的成本、收入和利润；日报不修改 Key 已结算金额或余额。
- 请求数按各层级内 `request_id` 去重，成功交付按 `winner` 去重。一个请求跨多个渠道/源分组重试，会同时出现在相关分项，因此分项请求数不可直接相加；成本和 Token 是所有 attempt 的可加总量。
- Token = 新鲜输入 + 输出 + 真实缓存写入 + 真实缓存读取。虚拟缓存是结算重分类，不再加一次 Token。
- 真实缓存命中率 = 成功 attempt 的缓存读取 Token /（新鲜输入 + 缓存写入 + 缓存读取），排除虚拟缓存和失败 attempt，沿用使用记录统计口径。
- 来源身份是“来源类型 + 渠道 ID”。源分组再按源组 ID 区分，ID 仅在本渠道内唯一；历史无 ID 时用快照名称。已知 ID 的组改名不拆成两组，按范围内最后一条日志显示名称。删除的直连渠道保留日志名称快照。

## 卖出倍率与渠道利润

在“网关组 → 编辑组”填写卖出倍率，保存后刷新每日报表即可看到该组流量带来的收入和渠道利润。它只用于报表估算，不改变下游返回的用量、网关 Key 的余额或已有结算。
卖出倍率可留空，或填写 0 到 1,000,000 之间的有限数字；上限与已有计费倍率保护一致，避免极端输入导致报表数值溢出。

- **预估收入**：仅计算已成功交付的请求，按**当前模型价格**和当时用量、虚拟缓存 Token 重算销售基数，再乘以所属网关组的**当前**卖出倍率，并归属最终获胜的渠道、源分组和请求模型。失败、丢弃、重试及未获胜的并发尝试不重复计收入。历史模型补价、涨价、降价、明确免费都会更新历史收入，原先为 0 或正数的结算均不锁死报表。
- **参考利润** = 预估收入 − 上游参考消费。所有已记录的上游尝试成本都扣除；只失败而无成功交付的渠道可显示负利润，这是未带来收入的实际尝试参考成本，不会被获胜渠道的收入掩盖。
- **利润率** = 参考利润 ÷ 预估收入 × 100%，可为负值。收入为 0 或存在待计价请求时，显示“—”，不显示无意义的百分比。
- **同一渠道跨网关组**：每个请求使用其所属网关组的卖出倍率，随后汇总到渠道及源分组；不同网关组不会互相套用卖出倍率。
- **零用量按 0 元计入**：Token 计费（含旧记录空计费模式）中，输入、输出、真实缓存读写、5m/1h 缓存写入明细、推理、图片 Token 全部为 0，且日志参考费用、已计费金额及匹配结算快照金额均为 0 时，预估收入按 0 元计入，不再因零结算或未配置卖出倍率阻塞参考利润。另计零用量异常，即使原始上游没有提供 usage 也使用这一报表约定，不据此声称上游实际免费。
- **不覆盖已知费用**：零 Token 但已有正数费用的记录仍保留其参考成本和原有收入判断，不擅自抹掉扣费依据；同一请求其他失败、重试、并发尝试的费用照常扣除。因此零收入请求仍可能产生负利润。只有 Token 计费可使用零用量例外，图片、按次或时长计费不因 Token 为 0 自动免费。有真实 Token 但缺单价的记录仍待计价。
- **留空与 0 不同**：除上述零用量零费用例外，留空表示尚未设置卖出倍率，不能按免费销售处理。成功交付请求缺少卖出倍率、所属网关组已删除或缺少可靠计价依据时，对应层级的收入、利润和利润率显示“—”，并标明待计价请求数；其他已完整计价的渠道仍正常展示。明确填写 0 表示免费销售，收入为 0，利润扣除全部成本。没有成功交付请求时，不需要卖出倍率也能确定收入为 0、利润为负的尝试成本。
- **历史口径**：修改卖出倍率后刷新即生效；保存、删除或同步模型价格后，后台分批重算所有历史参考成本及销售基数。升级后自动安排一次历史补算，可在“价格覆盖”查看进度或点击“重算历史费用与利润”。重算完成前报表可能暂时包含新旧价格。历史账务凭据 `billed_cost`、请求终态、winner 结算和实际 Key 余额保持不变，不向客户追扣差价。
- **重算销售基数**：优先使用 `reference_sales_base`，与不可变实际扣费分开存储。按日志的实际上游模型（为空才使用请求模型）、原始互斥 Token 桶和原始虚拟缓存 Token 计算，复用实时上下文阶梯及 5m/1h 价格；不套用当前虚拟缓存比例，不重复乘除上游倍率。虚拟缓存后的销售基数不高于未虚拟化基数。`reference_pricing_version > 0` 且基数为空表示本次没有可靠价格，不能回退到过时扣款冒充当前收入；明确配置免费则基数为数字 0。有用量但缺价格仍待计价。
- **尚未重算的兼容记录**：后台游标未到达的旧记录及新产生的记录沿用原有结算基数（历史 `billed_cost` 除以有效上游倍率，或无虚拟缓存旧记录的参考金额）；完成重算后使用新的销售基数。已经重算的零金额旧快照不会再阻止补价。
- **历史零用量**：该例外在查询时计算，升级后刷新历史报表即可生效，无需改写旧日志或执行历史费用重算；不修改任何结算快照、网关 Key 余额、响应校验规则或线上价格。
- **金额限制**：所有金额均以 USD 表示，属于参考毛利，不代表上游实际扣款或下游实收，也未计入服务器、支付手续费等经营费用。上游未报告的成本仍无法推断；不能将本报表视为财务对账单。

例如：同一请求先在渠道 A 失败、记录成本 $0.01，再在渠道 B 成功、记录成本 $0.03；若成功请求预估收入为 $0.10，则 A 收入为 0、利润为 −$0.01，B 收入为 $0.10、利润为 $0.07，总利润为 $0.06。收入不会因两次上游尝试被计算两遍。

## 实现

`GET /api/gateway/usage/daily-report?date=2026-10-21&timezone=Asia%2FShanghai`

日期省略时取所选时区当前日，时区省略时取 Asia/Shanghai。日期和时区非法返回 400；接口沿用管理端鉴权。

各统计层级均返回 `revenue`（预估收入）、`profit`（参考利润）、`profit_margin`（百分比，可为负）、`unpriced_requests`（待计价成功请求数）和 `zero_usage_requests`（Token 计费且所有真实用量桶为 0 的成功交付去重请求数）。异常笔数不要求费用为 0，因此已有费用但缺用量的记录也可被发现；已知费用不会被忽略。前三者允许为 null：有待计价请求时收入和利润为空，收入为 0 时利润率也为空。

数据库只读取所选自然日及前一日时间范围，通过一个 CTE 和五层聚合生成日、渠道、渠道模型、源分组、源分组模型结果；没有将原始使用记录加载到应用内存，也没有按渠道 N+1 查询。名称用最多三个固定批量查询补全。前端不自动高频轮询日报，点击刷新才重新汇总，避免后台重复扫描大日志。

回归覆盖北京时间跨日、DST 日界限、来源隔离、失败成本、真实缓存、跨组去重及 PostgreSQL 聚合。历史重价覆盖零/正结算快照的收入更新、五层报表、反复补价和删除价格、明确免费、原虚拟缓存 Token、上下文与缓存 TTL、失败成本保留、升级补算幂等及实际扣款不变；共享报表和游标用例同时由 SQLite 和 PostgreSQL 测试入口调用。
