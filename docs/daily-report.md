# 每日报表

入口：顶部导航“每日报表”，地址 `/daily-report`。

- 默认按 Asia/Shanghai（北京时间）自然日显示今日、昨日；可指定日期，查看所选日和前一日，也可切换 UTC 或浏览器本地时区。
- 两张汇总卡显示上游参考消费、预估收入、参考利润、利润率、去重请求数、成功交付数、上游尝试次数、Token 和真实缓存命中率，并标出消费最高渠道、该渠道消费最高源分组及模型。
- 渠道排行可按消费、利润或请求次数排序；利润排序将未计价项放在最后。渠道内展开源分组，再展开每个请求模型，均可查看收入、利润及利润率。消费最多模型和请求最多模型分别统计，渠道模型统计横跨该渠道所有源分组。
- 支持搜索渠道、源分组、请求模型。没有流量的日期显示空状态；没有有效输入 Token 样本时，缓存命中率显示“—”，而非伪造 0%。

## 统计口径

- 消费是使用日志的 `actual_cost`（USD 上游参考成本）合计，包括失败、拒绝、重试和并发尝试中已记录的成本。它不是上游站点发票或实际扣账，也不是用户网关 Key 的 `billed_cost`。上游未报告用量/成本的请求无法据此推断实际扣款。
- 价格覆盖的历史重算更新参考成本后，刷新日报读取更新后的金额；日报不修改 Key 已结算金额或余额。
- 请求数按各层级内 `request_id` 去重，成功交付按 `winner` 去重。一个请求跨多个渠道/源分组重试，会同时出现在相关分项，因此分项请求数不可直接相加；成本和 Token 是所有 attempt 的可加总量。
- Token = 新鲜输入 + 输出 + 真实缓存写入 + 真实缓存读取。虚拟缓存是结算重分类，不再加一次 Token。
- 真实缓存命中率 = 成功 attempt 的缓存读取 Token /（新鲜输入 + 缓存写入 + 缓存读取），排除虚拟缓存和失败 attempt，沿用使用记录统计口径。
- 来源身份是“来源类型 + 渠道 ID”。源分组再按源组 ID 区分，ID 仅在本渠道内唯一；历史无 ID 时用快照名称。已知 ID 的组改名不拆成两组，按范围内最后一条日志显示名称。删除的直连渠道保留日志名称快照。

## 卖出倍率与渠道利润

在“网关组 → 编辑组”填写卖出倍率，保存后刷新每日报表即可看到该组流量带来的收入和渠道利润。它只用于报表估算，不改变下游返回的用量、网关 Key 的余额或已有结算。
卖出倍率可留空，或填写 0 到 1,000,000 之间的有限数字；上限与已有计费倍率保护一致，避免极端输入导致报表数值溢出。

- **预估收入**：仅计算已成功交付的请求，使用历史结算计价基数（保留当时模型价格和虚拟缓存调整，去除上游倍率）乘以所属网关组的**当前**卖出倍率，并归属最终获胜的渠道、源分组和请求模型。失败、丢弃、重试及未获胜的并发尝试不重复计收入。优先采用不可变结算快照；旧记录回退后仍无可靠基数的请求标记为待计价。
- **参考利润** = 预估收入 − 上游参考消费。所有已记录的上游尝试成本都扣除；只失败而无成功交付的渠道可显示负利润，这是未带来收入的实际尝试参考成本，不会被获胜渠道的收入掩盖。
- **利润率** = 参考利润 ÷ 预估收入 × 100%，可为负值。收入为 0 或存在待计价请求时，显示“—”，不显示无意义的百分比。
- **同一渠道跨网关组**：每个请求使用其所属网关组的卖出倍率，随后汇总到渠道及源分组；不同网关组不会互相套用卖出倍率。
- **留空与 0 不同**：留空表示尚未设置卖出倍率，不能按免费销售处理。成功交付请求缺少卖出倍率、所属网关组已删除或缺少可靠计价依据时，对应层级的收入、利润和利润率显示“—”，并标明待计价请求数；其他已完整计价的渠道仍正常展示。明确填写 0 表示免费销售，收入为 0，利润扣除全部成本。没有成功交付请求时，不需要卖出倍率也能确定收入为 0、利润为负的尝试成本。
- **历史口径**：网关组当前卖出倍率用于重新估算所选日期；修改倍率后，历史报表随刷新更新。已保存的结算快照保持不可变，价格覆盖只重算其上游参考成本，不重写销售收入的历史基数。没有快照的旧格式记录若回退到参考金额，收入基数会随参考价格重算更新，因此不是历史成交价。虚拟缓存会影响下游销售计价依据，但不减少上游真实用量产生的参考成本。
- **结算基数**：优先使用成功 winner 的不可变结算快照 `billed_cost` ÷ 原日志有效上游倍率（正的 `billing_rate_multiplier`，其次正的 `rate_multiplier`，最后为 1），再乘当前卖出倍率。模型映射时沿用实际上游结算模型，而非拿请求模型另算一次。没有快照的记录先回退到正的历史 `billed_cost` ÷ 有效倍率；无虚拟缓存的旧格式记录还可使用正 `total_cost`（它已经是基数，不再除倍率），仅当缺少该值时用正 `actual_cost` ÷ 有效倍率。带 `attempt_status` 的新格式记录没有快照且 `billed_cost` 为 0 时仍待计价。若快照原始成本为正、虚拟缓存后的结算为 0，则可确认收入基数为 0；原始成本与结算均为 0 时无法区分免费和未知价格，标记待计价。明确卖出倍率为 0 不依赖历史基数。
- **金额限制**：所有金额均以 USD 表示，属于参考毛利，不代表上游实际扣款或下游实收，也未计入服务器、支付手续费等经营费用。上游未报告的成本仍无法推断；不能将本报表视为财务对账单。

例如：同一请求先在渠道 A 失败、记录成本 $0.01，再在渠道 B 成功、记录成本 $0.03；若成功请求预估收入为 $0.10，则 A 收入为 0、利润为 −$0.01，B 收入为 $0.10、利润为 $0.07，总利润为 $0.06。收入不会因两次上游尝试被计算两遍。

## 实现

`GET /api/gateway/usage/daily-report?date=2026-10-21&timezone=Asia%2FShanghai`

日期省略时取所选时区当前日，时区省略时取 Asia/Shanghai。日期和时区非法返回 400；接口沿用管理端鉴权。

各统计层级均返回 `revenue`（预估收入）、`profit`（参考利润）、`profit_margin`（百分比，可为负）和 `unpriced_requests`（待计价成功请求数）。前三者允许为 null：有待计价请求时收入和利润为空，收入为 0 时利润率也为空。

数据库只读取所选自然日及前一日时间范围，通过一个 CTE 和五层聚合生成日、渠道、渠道模型、源分组、源分组模型结果；没有将原始使用记录加载到应用内存，也没有按渠道 N+1 查询。名称用最多三个固定批量查询补全。前端不自动高频轮询日报，点击刷新才重新汇总，避免后台重复扫描大日志。

回归覆盖北京时间跨日、DST 日界限、已知源组改名、相同源组 ID 跨站点隔离、直连/监控 ID 冲突、失败成本、真实缓存、跨组请求去重、删除渠道名称、金额重算更新及 PostgreSQL 聚合。利润新增用例覆盖跨网关组卖出倍率、失败/并发尝试无重复收入、历史快照与参考重价隔离、虚拟缓存免费结算、未配置/删除组、缺失价格、0 倍率、负利润、空报表、HTTP 数字 0 与 null，以及极端数值的 JSON 安全性；共享金额用例同时由 SQLite 和 PostgreSQL 测试入口调用。
