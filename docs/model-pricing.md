# 模型价格同步与历史重算

## 管理入口

在「网关 → 价格覆盖」点击「一键同步 sub2api 最新价格」。固定读取官方仓库：

`https://raw.githubusercontent.com/Wei-Shaw/sub2api/main/backend/resources/model-pricing/model_prices_and_context_window.json`

同步仅接受有效 token 价目，HTTP 超时 30 秒、最大 8 MiB、不跟随重定向；网络或格式错误不修改当前配置。按量/图片的单次固定价格、Priority/Flex 服务等级价格不混入普通 token 单价。

同步更新来源为 `sub2api` 的条目，保留手工设置（包括手动停用）的条目。编辑同步条目后，该条目变为手动覆盖，下次同步不改写；删除它后，再次同步可恢复源价格。源中缺少的旧条目不会自动删除。

优先级：启用的价格覆盖（含供应商前缀、日期和常见别名匹配）→ 内置价目 → 已知家族回退。停用覆盖回退到内置价格，不会把模型变为免费。

## 上下文与缓存

- UI 单位是美元/百万 token，数据库和源数据使用美元/token。
- 输入上下文为新鲜输入 + **真实**缓存读取 + 缓存写入 token；虚拟缓存不改变所选档位。
- 超过阈值后，档位应用于**整次请求**，不是只计算超过阈值的部分。可配置达到阈值即生效；同步保留 xAI 的包含边界规则。
- 每档可分别设置输入、输出、缓存读取、5m 写入、1h 写入价格。档位价格留空沿用上一档；明确填写 `0` 表示免费。
- 5m/1h 区别对应**缓存写入保存时长**，不是缓存读取时长。基础 1h 写入价留空时沿用基础写入价，填写 `0` 为免费。
- 老记录缺少缓存保存时长明细时，未知写入部分按 5m/默认价格计算；明细与总量冲突时保留总量，避免重复计价。
- 同步解析源的 `*_above_Nk_tokens` 和显式长上下文阈值/倍率；缓存阶梯价格缺省时跟随对应输入倍率，明确源价格优先。

## 历史记录

保存、删除或同步价格后自动创建持久化重算任务，也可点「重算历史费用与利润」。每批最多 200 行，以创建任务时的最大记录 ID 为上界；进度存库，重启续跑，多进程通过 PostgreSQL 行锁串行处理游标。升级到支持历史销售基数重算的版本时，自动安排一次全历史补算；已经完成或正在运行的同版本任务不会因重启重复开始。

重算更新使用记录的参考成本拆分、总参考成本、乘源倍率后的上游参考成本、额外尝试成本，以及独立的 `reference_sales_base`。每日报表历史成本、收入和利润一起更新，包括原先结算为 0 的旧请求；不只补齐未知值，已计价历史记录也按新价更新。价格使用记录的上游模型（缺失则请求模型），成本保留当时源倍率，销售基数保留当时虚拟缓存 Token 并使用上下文阶梯和缓存 TTL，报表再乘网关组当前卖出倍率。

以下内容**不变**：原始 token、历史 Key 扣费/余额/额度、已结算实收 `billed_cost`、虚拟缓存结算、不可变请求终态和 winner 结算快照。重算不会向用户追扣差价，也不会伪造上游账单。

新格式且尚未写入请求终态的记录会跳过，避免与正在执行的结算竞争；未知模型价格清除旧参考销售基数、保留已有成本并计入跳过数，不再用旧价收入假装重算成功。不支持的非 token 计费、缺失用量但已知有费用的异常记录不清零。页面显示累计更新/跳过数。请求结束或补齐价格后，可再次重算。批次失败自动保留游标并在约 30 秒后重试；重算完成前汇总会暂时包含新旧参考价。

## 验证

回归覆盖源格式/大小/HTTP 错误、单价单位、阈值边界、5m/1h、明确免费与继承、别名覆盖、手工价保护、历史不重扣、游标续跑。`TestPriceRepricingPostgres` 使用 `UPSTREAM_OPS_TEST_POSTGRES_DSN`，覆盖多 worker 互斥和历史页读取后恰好完成结算的竞态；由 GitHub CI 执行。
