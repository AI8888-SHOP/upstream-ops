# 智能比价与路由策略

首页搜索栏旁的「智能比价」可以读取所有匹配的源分组名称和简介，由配置的大模型提取价格，再由服务端按同规格实际成本排序。搜索覆盖全部渠道，不限当前分页；「仅展示已创建密钥的分组」的可见性规则仍生效。需要先同步渠道，价格数据取自本地最新采集的分组说明。

## 使用

1. 在「智能比价 → 比价大模型配置」填写完整 Chat Completions 接口地址（例如 `https://你的接口/v1/chat/completions`）、模型和 API Key。使用兼容接口的非流式 JSON 文本响应。密钥加密保存，不会回显；更换地址时必须重新填写密钥。
2. 输入搜索词、完整规格（具体模型、分辨率、视频时长等）、货币及计价单位。例如「指定图片模型，2K，单张」「CNY」「张」。可填写速度、稳定性等补充分析要求；排序仍以同规格实际成本为先。
3. 点击「分析并生成策略」，核对原文、换算说明、参考成本和不确定项。分析会将渠道名称、分组名称、简介和相关倍率发送给配置的模型，不发送渠道登录信息、会话或上游密钥。单次最多 100 个源分组，超过限制会要求缩小范围，不会静默截断。
4. 点击「保存策略」。从首次保存起有效 30 分钟，重复点击不会续期。未保存的分析草稿也会在 30 分钟后过期。
5. 进入目标网关组的「渠道路由 → 应用比价策略」，查看策略后点击「一键添加全部并排序」。所有候选会合并到当前草稿；已有路由保留密钥、禁用状态、模型限制和自定义计费设置，不重复添加相同渠道的同一源分组；不在策略中的路由也会保留。
6. 检查后点击「保存路由」。新路由依旧需要「确保上游密钥」。应用不会替你解除禁用、冷却或改动网关组限价。

## 价格口径

- 最终实际支付价格直接比较，不再重复乘分组倍率和充值倍率。
- 明确为分组内余额扣费的价格，按渠道「充值倍率」的乘/除模式换算。需要手动配置充值换算值；没有折扣请填 `1`。
- 明确为未包含分组倍率的余额基础单价，先乘原始分组倍率，再做充值换算。已换算过的展示倍率会先还原。
- 规格、单位或货币不一致，价格依据不明，或者无法判断是否已经包含倍率的，均标记「待核实」，排列在已知价格之后。不会自动猜测汇率。充值换算值不代表跨币种汇率；跨币种报价需先统一口径。
- 大模型可能理解错误。界面会展示源说明及其引用，应用前需要核对。无价格的候选也会保留，符合「全部添加」的行为，但不会当作 0 元低价。

## 优先级与调度

应用策略会替换当前组原有的比价优先级。正整数越小越优先，相同价格共享一个优先级；`0` 表示自动，位于指定优先级之后。可在每条路由修改，或点「清除比价优先级」后保存，回到原有调度。

优先级独立于计费倍率，保存路由和自动倍率重排不会把它覆盖。实际选路在可用、未冷却、符合模型及限价约束的候选中执行。并发已满的来源让位，已领取的恢复探测仍按原规则执行，备用路由仍在普通路由之后；同一优先级内部保留现有速度、负载、缓存和会话亲和排序。多路并发或失败换源仍可能使用后面的渠道。

30 分钟限制的是**可应用窗口**。应用并保存到组里的优先级不会在 30 分钟后自行撤销。它影响该组的路由顺序，**不会根据每个请求的分辨率自动切换策略**；建议对不同规格使用相应的网关组。若源分组被删除，或名称、价格描述、相关倍率变化，应用时会拒绝旧策略，需要重新分析。

## 验证

回归用例覆盖换算、证据缺失、不同币种/单位、重复和虚构候选、策略过期及价格变化、已有路由合并、计费倍率保持、调度优先级与禁用/负载/恢复探测。Go 测试和前端测试由 GitHub CI 运行；本次开发按要求不在本机编译。
