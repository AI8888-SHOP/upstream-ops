# 使用记录表头与速度

- 使用记录表头从列配置生成，和列显示开关、数据单元格使用同一顺序；补齐“渠道分组倍率”，避免类型、计费模式、Token、费用及后续列错位。
- 延迟栏增加 `TPS ≈`，为本次上游尝试的输出 Token ÷（本次尝试总耗时 − 本次尝试首字耗时），单位 Token/s。
- TPS 不使用包含先前重试等待的整请求耗时，避免把其他尝试的等待算入本次生成速度；时间差仍可能包括本次准备和处理开销，输出 Token 也可能包含上游计入的推理 Token，所以展示为估算值。
- 非流式、已识别的图片/视频请求、缺失首字、没有正输出或有效时间差时显示“—”，不伪造吞吐量。

## 历史价格与实收

使用记录的“上游”副行和费用明细显示可随价格覆盖重算的上游参考成本。新格式已结算记录的实收固定使用 `billed_cost`，包括零金额；历史改价不会修改已经结算的 Key 额度或账本。上游参考成本不等于站点实际扣账，无法用缺失用量的日志推断真实收费。

前端回归检查位于 `frontend/tests/usage-table.test.mjs`，涵盖列顺序结构、TPS 边界和零实收费；价格表单的 per-token 与 $/MTok 换算、上下文阈值、空值继承和显式零价位于 `frontend/tests/pricing-form.test.mjs`。测试由 GitHub CI 执行。
