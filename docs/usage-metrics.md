# 使用记录表头与速度

- 使用记录表头从列配置生成，和列显示开关、数据单元格使用同一顺序；补齐“渠道分组倍率”，避免类型、计费模式、Token、费用及后续列错位。
- 延迟栏增加 `TPS ≈`，为本次上游尝试的输出 Token ÷（本次尝试总耗时 − 本次尝试首字耗时），单位 Token/s。
- TPS 不使用包含先前重试等待的整请求耗时，避免把其他尝试的等待算入本次生成速度；时间差仍可能包括本次准备和处理开销，输出 Token 也可能包含上游计入的推理 Token，所以展示为估算值。
- 非流式、已识别的图片/视频请求、缺失首字、没有正输出或有效时间差时显示“—”，不伪造吞吐量。

## 历史价格与实收

使用记录的“上游”副行和费用明细显示可随价格覆盖重算的上游参考成本。新格式已结算记录的实收固定使用 `billed_cost`，包括零金额；历史改价不会修改已经结算的 Key 额度或账本。上游参考成本不等于站点实际扣账，无法用缺失用量的日志推断真实收费。

## 程序 API 调用记录

管理端网关新增“API 调用记录”，通过 `/api/gateway/api-calls` 和 `/api/gateway/api-calls/stats` 查询独立审计账本。它覆盖网关真实转发、验糖、模型恢复探测、管理模型测试、解释模型请求，以及渠道和同步管理接口；渠道管理 GET/登录/密钥操作与模型生成请求使用不同用途筛选。默认分页，支持时间、模型、渠道、源分组、上游 Key 名称和状态过滤。

每次 HTTP attempt 在发送前先写入 pending，完成后补充状态、耗时、上游请求 ID 和已知用量；发送前审计写入失败会终止该次出站调用，防止出现新的无记录调用。进程中断留下的 pending 仍保留以供核查，不能当作成功或零费用。失败、重试与重定向分别留行；`request_id` 唯一标识一次真实出站调用，`gateway_request_id` 关联同一网关逻辑请求的业务使用记录。复用验糖结果只记录复用事件及原始调用 ID，不新增真实调用行。

审计不保存认证头、请求正文或完整响应正文，路径不含 query/fragment，常见含凭据的路径段会脱敏。流式按有界事件提取最终 usage，支持 OpenAI Chat、Responses 与 Anthropic；缺失或不完整用量保留未知，不凭输入提示或总 token 数推算成本。超过解析上限或上游未返回 usage 时，次数与状态仍有记录，用量及成本可能未知。

`estimated_cost` 是按当前模型价格和源路由账号倍率计算的运营参考成本，未取得足够用量、倍率或价格时为空。它不代表已从上游账单核验的实付金额，真实零成本和未知成本分别展示。按次计价也仅在配置有效且上游请求成功时估算。这套账本不执行客户 Key 扣额、赢家结算或缓存健康采样；客户业务使用记录保持原本计费语义。

这次升级开始记录新的程序调用。过去未存档的检测用量或费用不作虚构回填。审计删除接口至少保留 90 天；当前未默认启用自动删除。验糖事件也改为按时间保留 90 天，不再只保留每路由最新 100 条（界面仍可仅展示最近 100 条）。

前端回归检查位于 `frontend/tests/usage-table.test.mjs`，涵盖列顺序结构、TPS 边界和零实收费；价格表单的 per-token 与 $/MTok 换算、上下文阈值、空值继承和显式零价位于 `frontend/tests/pricing-form.test.mjs`。测试由 GitHub CI 执行。
