# 调度首字等待与故障转移

本次修复覆盖普通串行转发，以及响应校验/并发兜底使用的协调转发。

## 失败处理

- HTTP 429、503 优先换源，不再重复请求同一路由。首字超时、本地并发排队超时也跳过同路由重试。
- 校验命中的 HTTP 429/5xx，以及明确的协议内过载、限流、服务错误等，不再绕过健康冷却。保留校验规则字段，同时记录上游错误类型。普通回答内容命中规则仍按原有校验重试配置处理，不因此共享冷却。
- 协调转发在失败尝试完成后更新健康状态，不再等待胜出流的整段回答结束；最终使用日志沿用已设置的冷却时间，不重复延长。
- 首字超时冷却继续受网关组开关控制，且仅影响当前网关组的对应模型。本地排队超时、请求总预算耗尽、客户端取消均不触发上游冷却。

## 网关组新增设置

| 字段 | 范围 | 含义 |
| --- | --- | --- |
| `request_first_token_timeout_sec` | 0–1800 | 流式请求首字总预算。0 继承全局单次转发超时（默认 600 秒），但以整个入站请求为计时单位。 |
| `request_max_attempts` | 0–64 | 每个请求的总尝试上限，包含首次、重试、顺延和并发请求。0 沿用原有各项次数限制。 |

总首字预算包括入口准备、并发排队、前面的失败尝试、协议转换和响应校验等待。所有候选共享同一计时器，最后候选也不能重新获得一份预算。首个有效输出刷新至下游后停止此计时器，后续回答仍遵循原有单次转发/流式超时。

已有 `first_token_timeout_sec` 仍是单次尝试的快速换源阈值，其最后候选兼容规则保留；请求总预算独立生效。新增设置默认值为 0，自动迁移不会替用户设置统一的短首字超时。高推理强度和长上下文应选择适合的预算。

总尝试预算只在准备执行新尝试时消耗；因前面错误而跳过的重试计划不占用名额。用完名额后不启动新的上游请求，已经发出的并发候选可以继续竞争结果。

## 使用记录

- `first_token_ms`、`duration_ms`：保留单次尝试口径及历史数据。
- `request_first_token_ms`：从进入网关到首个有效内容写出并调用 Flush 的时间，仅在选定响应的流式记录中保存。
- `request_duration_ms`：同一请求从进入网关至记录用量时的耗时。
- 使用记录优先显示新增请求指标，同时保留尝试首字；历史记录明确显示为尝试口径。没有有效内容的请求不会用角色声明、usage、错误帧或心跳补造首字。

首字识别覆盖 Chat、Responses、Anthropic 的文本、推理文本和工具调用。只扫描首次输出前的有界 SSE 前缀，之后停止解析；请求热路径不查询历史使用日志。网关 Flush 时间不是终端屏幕展示时间，分析下游额外延迟仍需关联下游日志。

请求时间字段由既有 AutoMigrate 管理，无需回填历史使用记录。

## 倍率约束下的动态选路

在编辑网关组中选择选路策略：

- **倍率优先 `cost`**：保留现有倍率顺序、会话亲和与前 N 个来源轮询。已有组升级后继续使用此模式。
- **均衡 `balanced`**：优先选择达到首字目标、平滑失败率不超过 10% 的便宜来源；没有达标来源时，按综合等待评分选择。
- **首字优先 `latency`**：在倍率范围内按首字、失败率与负载选择。速度接近（评分相差不超过 15%）、同样达标状态且未满载时，保留会话来源。

动态策略目前用于流式文本请求。图片/视频生成、实时连接及非流式请求保留原调度策略，不把这些耗时与文本首字混合统计。原有负载均衡渠道数对动态策略不生效；动态策略评估倍率范围内所有可调度候选，不会默认开启并发竞速。

| 配置 | 范围 | 新建组预填值 |
| --- | --- | --- |
| `scheduling_mode` | `cost` / `balanced` / `latency` | `cost` |
| `scheduling_premium_percent` | 0–1000% | 20% |
| `scheduling_window_minutes` | 1–60 分钟 | 5 |
| `scheduling_min_samples` | 1–1000 | 10 |
| `scheduling_target_ttft_sec` | 1–300 秒 | 10 |

相对上限 = 本次请求开始时最低可用来源的有效倍率 × (1 + 允许溢价 / 100)。同时遵守已有最大计费倍率。0% 只允许最低倍率；升级已有组的溢价初始值为 0%，管理员可自行调整。普通故障转移、同路由重试及并发备选共同遵守本次上限，便宜来源失败后不能逐级提高预算。预算内全部失败时返回失败，不自动购买更贵来源。恢复探测仍走原有受控恢复路径，也受倍率硬上限约束。

例如 A 倍率 0.05、首字 20 秒、成功率 85%；B 倍率 0.055、首字 5 秒、成功率 99%；C 倍率 0.08、首字 2 秒。在允许溢价 20% 的情况下，上限为 0.06，优选 B，C 不参与。虚拟缓存百分比不参与价格或速度评分。

### 统计与边界

- 统计键包含网关组、实际上游渠道/直连来源、源分组、凭据指纹、映射后模型、有效推理强度、入站端点，以及原请求体大小档（≤16 KiB、≤64 KiB、≤256 KiB、超过 256 KiB）。大小只是输入规模近似，不是 Token 数；不保存原请求内容或明文密钥，也不按客户端网关 API Key 混算上游。
- 直连来源更换密钥或地址后使用新指纹。监控来源指纹基于加密凭据，重新加密同一密钥可能导致保守地重新学习。不同网关组分开统计，避免不同超时/校验策略互相污染；上游真实健康冷却继续按既有规则共享，首字超时冷却继续只作用于当前组。
- 有效内容真正 Flush 时立刻写入单次尝试的首字样本，不等待长回答完成，不包含前面其他来源失败所花的时间；包含本次尝试的本地排队、准备及校验延迟。失败请求即使没有任何首字也进入失败统计；没有有效输出的空成功响应视为不可用结果。客户端取消、并发落败、本地排队超时、配置错误、HTTP 400/413/422 请求错误和整个请求预算耗尽不算独立上游失败。
- 使用固定分钟桶，对近期样本赋予更高权重，首字估计结合均值和近似 P90。窗口内样本不足时参考同一统计键的最近 60 分钟；仍不足则向目标的 1.25 倍收缩。失败率使用少量先验平滑，综合评分加入失败等待损失与当前负载。P90 是直方图区间上界估计，不是精确分位数。
- 未经充分观测的来源不会仅凭保守初始值压过已有充分样本且可靠的来源。约 5% 的新首选机会探索倍率内、未满载、低样本且无明显失败的来源；不额外发请求，不在每次重试重复探索，也不打断表现接近的会话亲和。所有来源都无样本时按价格和负载开始学习。
- 并发负载来自现有并发控制器，按物理上游渠道共享；同一渠道的不同源分组读取相同活跃数与排队数。存在预算内未满载候选时优先使用；全部满载时仍保留可用候选，按现有排队/请求预算处理。快照不能预留名额，最终由并发控制器原子分配。
- 每进程最多保存 4096 个统计键，每键固定 60 个分钟桶，按最近写入淘汰旧键；超过 60 分钟的数据不再参与评分。请求路径不查询历史使用日志，不新增周期性数据库聚合。当前统计驻内存，重启后重新学习，多实例不共享速度统计；选路依据随既有用量记录持久保存。暂未实现统计快照恢复。

使用记录的延迟栏新增“调度依据”，展示选择时的原因、有效倍率/本次上限、样本数、窗口、首字均值、近似 P90、平滑失败率及物理渠道负载。综合等待评分是选路参考，不承诺请求一定在该时间内开始输出。

## 验证

回归场景包含：校验命中的过载不重复重试、失败冷却在备用源启动前可见、跳过计划不消耗总尝试预算、并发共享次数限制、元数据不算首字、拆分 SSE 帧、总预算取消上游并释放并发槽位、首字交付后不因首字预算中断长回答，以及配置保存和重置。

动态选路回归用例覆盖倍率示例、相对/绝对硬上限与零溢价、失败后保持上限、两种模式、满载与软亲和、低样本探索、统计隔离/过期/内存上限、首字即时反馈、并发下只记一次结果，以及普通/协调转发到用量记录的完整链路。

运行位置：GitHub Actions 既有 CI，执行 Go 测试、race 检查及前端检查。本次本地仅做源码格式/差异检查与前端 ESLint，不执行 Go 测试或构建。需要在后续推送后确认 CI 结果，再小范围开启新策略，对比请求级首字与实际费用。
