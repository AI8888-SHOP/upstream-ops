# 网关组首包保活

在“网关 → 编辑组”中，可为单个网关组开启首包保活，并设置随机延迟区间。默认仅提前建立流连接、发送 SSE 注释，不生成模型回答。主开关、sub2api 首字统计兼容和多层合成首响应开关均默认关闭；已有组不会因升级自动切换行为。

## 配置与时序

- 延迟单位为毫秒，必须满足 `0 <= 最小值 <= 最大值 <= 60000`；每次请求在包含两端点的区间内随机选择一次延迟。最小值等于最大值时使用固定延迟。
- `0 / 0` 表示准备完成后尽快发送首包，不保证请求抵达服务器的同一瞬间发出。
- 计时从鉴权、请求体解析、初始路由与响应校验配置准备完成后开始；无权限、无可用模型路由等在此之前发现的错误仍按原方式返回。
- 上游若更快返回可交付内容，立即透传，不为满足随机延迟而等待。
- 定时器先到时，发送 HTTP `200`、`Content-Type: text/event-stream` 并刷新连接。默认发送一条 SSE 注释：

  ```text
  : upstream-ops keepalive

  ```

- 在尚未交付实际流内容时，每隔 15 秒发送保活注释。实际流开始后停止预连接定时器，沿用现有流式保活机制。
- 请求结束、客户端取消或写入失败时停止定时器；保活不延长请求的真实首字超时预算。

## sub2api 首字统计兼容（可选）

需要让下游 sub2api 的 **Responses / semantic** 首字统计识别提前建流时，可额外开启“sub2api 首字统计兼容（Responses / semantic）”。未开启下方多层合成首响应时，无需修改 sub2api 源码，但 sub2api 的“OpenAI Responses 首 token 统计口径”必须选择 `semantic`；`visible` 口径仍等待真实可见输出，不会把空 reasoning 项计为首字。不同协议、转换路径或不同下游实现不保证采用相同统计规则。

此模式只适用于同时满足以下条件的请求：

- 主保活开关与兼容开关均开启，入站为 `/v1/responses` 流式文本请求。
- 请求明确包含 `"store": false`；省略 `store` 或设置为 `true` 不启用兼容前缀。
- 不使用 `previous_response_id` 续接、`conversation` 会话或后台模式；`background: false` 可以使用。
- 仍符合普通保活范围：不是已识别的媒体生成请求，也不是 WebSocket。

不符合这些条件时自动退回普通 SSE 注释，不修改响应标识或模型事件。上游内容早于定时器就绪时直接透传，不生成兼容前缀，也不重写响应。

符合条件且定时器先到时，网关先发送完整的 `response.created`、`response.in_progress` 事件和包含空 reasoning 项的 `response.output_item.added` 事件。sub2api 的 `semantic` 统计可由该空项目启动；这只是提前观察到语义事件，**不是模型已生成回答或实际推理内容**。等待上游期间仍发送普通 SSE 保活注释。

为保证后续流的事件身份和顺序一致，兼容响应使用网关生成的响应 ID；真实流合入时处理重复生命周期事件、事件序号和输出索引，终端响应包含该空 reasoning 项。回答文本和工具参数的内容不变，真实上游 ID 与模型信息仍用于网关内部诊断、校验和使用记录。

### semantic 空事件模式的使用限制

- 该模式仅用于明确不保存状态的请求。网关生成的响应 ID 不是上游保存的响应，**不能用于后续 `previous_response_id` 续接或按 ID 查询上游响应**。需要保存或续接时使用普通保活模式。
- 消费方会看到额外的空 reasoning 项，不能假定 `output[0]` 一定是正文；应按项目类型读取内容。建议先用实际 SDK 和下游代理验证后再逐组开启。
- 只改变符合上述统计口径的下游所记录的时间，不改变网关的真实首字、胜出选择、响应校验、重试或切换策略，不改变 Token 用量和计费。
- 不延长网关的真实首字超时或请求总预算，也不能承诺绕过下游自己的真实输出超时检测。
- 配置延迟不等于下游最终展示的 TTFT：下游起算位置、网络传输、代理缓冲和事件处理都会带来额外耗时。不能保证设置 100 毫秒就记录为 100 毫秒。
- 提前发出的生命周期事件不代表请求成功；失败仍按下文以流内错误结束。

## 合成首响应：多层 sub2api 兼容（可选）

第一层 sub2api 可以把空 reasoning 事件计入 `semantic` TTFT，但在其首输出暂存阶段，不一定立刻向下一层转发。因此，上游已提前建流不代表后面的 sub2api 也会提前收到可计时事件。

需要多层转发时，在主开关与 sub2api 兼容开关均开启后，再开启“合成首响应（多层 sub2api 兼容）”。该选项默认关闭，仅在上述所有无状态 Responses 条件满足时生效，沿用相同的随机延迟；不符合条件时仍使用普通保活注释。

该模式在兼容生命周期与 reasoning 项之后，增加合法的 reasoning summary 事件，包含**单个空格**的 `response.reasoning_summary_text.delta`。这不是零内容保活：下游会收到合成的推理摘要内容。现有 sub2api 的 `semantic` 与 `visible` 口径均可将该非空 delta 识别为输出，并将其转发到下一层，无需改动下游代码；不保证任意代理版本、代理缓冲或协议转换路径都有效。

使用前必须了解以下影响：

- 合成空格会让下游认为已经开始输出，**解除各层 sub2api 的首输出超时保护，并可能影响之后失败时的无损重试或换源**。我们的程序无法继续控制下游代理的超时和重试决策。
- 本网关仍区分合成首响应与真实上游内容：真实 TTFT、真实首字预算、胜出选择、校验、上游失败换源、Token 用量与计费逻辑不因合成空格提前触发。后续若最终失败，仍按失败结算并返回流内错误，不伪造成功。
- 真实回答文字、工具调用参数和上游用量不被替换，但响应中额外存在带单个空格摘要的 reasoning 项；不能依赖 `output[0]` 是正文。
- 与 semantic 空事件模式一样，响应使用网关生成的 ID，不能拿该 ID 继续会话或查询上游响应；仅适用于明确 `store:false` 的无状态请求。
- 多层可提前展示的 TTFT 是合成首响应时间，**不代表模型更快产生回答、推理或工具结果**。实际数值仍包括网络、代理缓冲与计时起点差异，不保证等于配置延迟。
- 如需保留下游自己的真实首输出超时与尽可能完整的换源能力，不开启此选项；如果仅需维持连接，则只开启普通保活。

## 适用范围

仅作用于设置了 `stream: true` 的文本流式请求：`/v1/chat/completions`、`/v1/completions`、`/v1/responses` 和 `/v1/messages`。非流式请求、已识别的图片/视频等媒体生成请求，以及 WebSocket Upgrade 请求不启用。文本对话包含图片输入与生成图片输出是不同情况；范围判断沿用请求内容和路由映射后的模型识别。

## 成功、错误与客户端兼容性

提前发送的 HTTP `200` **只表示流连接已建立，不表示模型请求成功**。此后网关仍按原策略执行上游尝试、重试、切换、并发优选和响应校验；保活注释或兼容前缀不能让某次尝试被选中，也不能让被拒绝的响应通过校验。

若所有可尝试路由最终失败：

- 尚未发送保活首包时，返回原 HTTP 错误状态和 JSON 错误体。
- 已发送 `200` 和保活注释或兼容前缀时，HTTP 状态不能再更改；改用客户端协议对应的 SSE 终端错误结束流：Chat 为错误数据和 `[DONE]`，Responses 为 `response.failed`，Anthropic 为 `error` 事件。终端错误包含网关请求 ID，保留可读取的错误类型和错误代码；使用记录仍记录实际失败。

客户端必须识别流内错误，不能仅凭 HTTP `200` 判断成功。某些 SDK 或下游代理仅在收到 HTTP `502` / `503` 等状态时自动重试；提前建立流连接后，这类自动重试行为可能变化。建议先在目标客户端验证兼容性，再逐组开启。

提前发送响应头后，上游稍后返回的请求 ID、限流信息等响应头无法追补到已发出的 HTTP 头部；故障定位应使用网关请求 ID 和使用记录。

## 不改变的指标与限制

- 普通保活模式不生成文本 delta、生命周期事件、用量数据或伪造的成功结束事件。semantic 兼容模式额外生成生命周期前缀和空 reasoning 项；多层模式再增加单个合成推理摘要空格。两种模式均不伪造工具参数、用量或成功。
- 注释及兼容前缀均不计入网关真实 TTFT、不改变 Token 用量和计费，不解除单次尝试及整请求的真实首字预算。
- 不改变上游实际生成速度，不保证降低下游测量的首个内容 Token 延迟，也不保证上游最终成功；semantic 统计提前不能作为真实速度提升。
- 注释可能缩短客户端观察到的首字节等待并维持连接，但代理缓冲或客户端忽略注释等行为仍影响实际体验。

相关配置字段为 `stream_preconnect_enabled`、`stream_preconnect_sub2api_enabled`、`stream_preconnect_multihop_enabled`、`stream_preconnect_min_delay_ms` 和 `stream_preconnect_max_delay_ms`。省略字段时保留原配置；两个兼容开关均默认 `false`，旧组升级不会自动开启。多层模式仅在三个开关均开启时生效。关闭主开关即可恢复等待真实上游响应后再建立流连接的原有方式；关闭父开关时保留兼容开关偏好，只有依赖的父开关重新开启后才可能生效。
