# 渠道路由支持模型与映射

在 **网关 → 选择网关组 → 渠道路由 → 支持模型** 为每条路由单独设置：

- **全部模型**：默认值，不额外限制当前路由。已有路由升级后保持此行为，不表示上游实际支持任意模型。
- **仅选中模型**：只调度选中的上游模型。可以拉取模型后勾选，也可手动填写，每行一个或用逗号分隔。

点击“应用到路由”后，再点击页面的“保存路由”生效。选择“仅选中模型”但列表为空，表示这条路由不支持任何有模型的请求，而不是恢复全部。

## 单渠道模型映射

在同一个“路由支持模型与映射”弹窗中，可给**这条路由**添加“客户端模型 → 上游模型”映射。例如 `chat-fast → upstream-fast`，会将发往该渠道的请求体 `model` 改成 `upstream-fast`；其他路由仍保留各自的配置。

- 支持精确匹配和 `*` 兜底映射；精确匹配优先。每个客户端模型只能配置一次，不完整或重复的映射会在应用时提示。
- 保持既有解析顺序：先应用路由映射，再应用网关组映射；每层只解析一次。若组级存在相关映射，它仍可能继续改写路由映射的结果。
- “仅选中模型”应填写**最终上游模型 ID**，不能只选择客户端别名；直连渠道自身的模型限制仍然生效。
- 映射与支持范围一起应用到路由草稿，再通过“保存路由”统一生效；取消弹窗不会修改草稿。清空映射后保存会删除本路由映射，不影响组级映射。
- 普通/流式转发、故障转移、并发备选、模型探测和糖果题检测沿用同一套路由映射。

## 作用范围

- 按路由保存，不修改监控渠道账号、源分组或上游 API Key 的权限，也不修改其他网关组。
- 按**映射后的最终上游模型 ID**精确匹配，区分大小写，不支持通配符。例如客户端 `chat-fast` 映射到 `upstream-fast`，应选择 `upstream-fast`。
- 直连渠道路由同时受两层限制：路由支持模型与直连渠道自身可用模型取交集。路由选择全部不能放宽直连渠道限制。
- 普通请求、流式请求、故障转移和并发备选都从过滤后的候选池选路；自动解除冷却不会绕过手动设置的支持模型范围。
- 自动聚合 `/v1/models`、组模型同步、手动模型测试和冷却恢复探测遵守路由限制。共享冷却的原路由不再支持该模型时，会选择同一共享上游凭据下仍支持它的活动路由探测。
- 手动/混合模式中的自定义模型列表仍由管理员维护；列出某个模型不代表可以绕过实际选路限制。
- 不带模型的模型发现、资源查询等请求保持原有行为。

## 拉取模型

拉取使用**已保存的路由及其上游密钥**，不会自动创建密钥、保存草稿或发起模型生成。新路由应先保存；监控渠道还需要“确保上游密钥”。修改来源或源分组后也需先保存再拉取。上游不支持模型列表时，可以直接填写模型 ID。

模型候选拉取不会套用当前路由的白名单，否则无法勾选白名单之外的新模型；直连渠道自身的模型限制仍然保留。刷新候选不会覆盖当前选中项。

## 接口与持久化

`PUT /api/gateway/groups/:id/routes` 的每条路由增加：

```json
{
  "model_policy": "allowlist",
  "allowed_models_json": "[\"upstream-fast\",\"upstream-pro\"]",
  "model_mapping": "{\"chat-fast\":\"upstream-fast\"}"
}
```

`model_policy` 为 `all` 或 `allowlist`，默认 `all`；模型列表为 JSON 字符串数组，保存时去掉首尾空格、空项和重复项。非法策略或非法 JSON 拒绝整次保存。

`GET /api/gateway/groups/:id/routes/:route_id/models/preview` 返回已保存路由的公开字段和 `available` 模型列表，不返回上游密钥，且校验路由属于该网关组。

新字段通过现有 AutoMigrate 添加，不需要手工执行 SQL；保存路由会失效对应组的路由与模型列表缓存。克隆网关组会保留模型策略。

渠道级映射复用现有 `model_mapping` 字段，无额外数据库迁移；克隆网关组时也会保留每条路由的映射。
