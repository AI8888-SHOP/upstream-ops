## 本地修改

1. 开启普通顺延时，优先尝试其它候选；已选择换源的失败路由不会再消耗同源重试额度。规则拒绝不再把同源重试插到未试候选之前。没有备选或明确关闭顺延时保留同源重试策略。
2. 在显式 error / response.error 中识别模型不可用、上游密钥失效、余额不足。即使未开启全部 4xx 顺延，这些错误也可按组的重试／顺延额度换源；不扫描正常回答或工具参数，不对普通参数错误默认广播重试。
3. 这类 400/404 不再作为普通调用方参数问题漏出源站失败统计；模型错误匹配正则时也跳过无意义的同源重试。
4. 首字样本不足时可借用 60 分钟历史，但近期已有足够失败结果时保留近期失败率，避免故障期被旧成功记录冲淡。评分增加真实失败耗时惩罚，保留倍率硬上限、负载因素与有限探索。
5. 请求已用到最后一次实际尝试时，或剩余备选已被排除／禁止重试时，不再为了不存在的下一次机会提前触发换源首字计时器；共享请求总预算仍然有效。尝试额度耗尽后，失败健康记录也不再被计划里无法启动的后续同源重试阻止。
6. 编辑组提示总次数与顺延次数冲突；使用记录展示独立的首字／结果统计窗口及失败平均耗时。
7. 协调转发中的普通不可重试 HTTP 错误作为失败结束，保留真实状态及错误正文，不再把空流缓冲选为成功响应；此类调用方错误不触发模型冷却。

## 上线配置建议（未自动应用）

先验证新代码，再对单个组灰度启用 latency 模式。可从 5 分钟窗口、10 个样本、10 秒首字目标开始；保留既有倍率上限，不自行放宽允许溢价。每请求总次数至少覆盖打算尝试的独立候选，例如当前三个启用源可先设 3 次、同源重试 0 次；设置一个能被下游等待上限容纳的请求首字总预算。

单次首字阈值及 hedge 延迟需要参考按模型／推理强度分组的 P90，不统一盲设。Hedge 会同时发出额外请求，取消也未必能阻止上游计费，需作为明确开启的成本换延迟选项，不自动启用。

不得承诺绝对 100%：全部源故障、无任何源支持请求模型、用户主动取消、硬预算耗尽及已输出后的中途断流都存在不可重试边界。不偷偷降低模型、突破费用上限、伪造成功或拼接不同流。需要更高可用性，仍须配置独立且有余额、模型真实可用的备用来源。
