# 上游连接健康与模型查询

网关复用 HTTP/2 长连接。单个请求超时只会取消对应的 HTTP/2 流，不能保证底层连接立即关闭；如果对端不再读取，取消帧也可能被堵住，后续请求复用同一连接后会继续超时。

连接层采用以下保护：

- 30 秒未收到任何 HTTP/2 帧时发送 PING；10 秒未收到确认则关闭异常连接。
- 有待发送数据但连续 15 秒无法写入时，终止阻塞的写入并淘汰连接。
- 健康检查只判断连接是否响应。上游仍能确认 PING 时，可以继续等待模型生成，真实首字超时和流空闲超时仍按现有配置执行。

`GET /v1/models` 使用与生成转发隔离的连接池，并按上游地址与代理配置分开。遇到连接超时、传输失败或成功响应的正文读取失败时，淘汰对应查询池，使用新连接重试一次。每次尝试最多 15 秒，总请求预算仍为 30 秒；调用方取消后不再重试，也不会因为用户取消淘汰连接池。HTTP 错误响应、鉴权和模型列表解析错误直接报告；HTTP 错误正文若传到一半断开，会淘汰连接池，但仍保留原状态码和已收到的错误信息，不重试该错误。

监控渠道与直连渠道使用相同保护，保留各自的代理、鉴权和额外请求头，每次 HTTP 尝试均进入 API 调用审计。生成请求不使用这层额外重试，继续由网关现有的首字预算、换源及计费流程处理。
