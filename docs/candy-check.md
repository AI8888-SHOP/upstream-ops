# 不降智检测（糖果题）

入口：网关 → 选择组 → 编辑组 → 不降智检测（糖果题）。默认关闭。

渠道路由的每一行提供「智商测试」按钮，使用已保存的网关组检测模型、推理强度和渠道配置立即执行一次糖果题。无需开启定时检测，但须先填写并保存检测模型。测试中显示忙碌状态，完成后展示答案、通过/失败、耗时和原因；刷新结果不会覆盖未保存的路由编辑。

手动测试可跳过等待周期并在冷却中复测，不会在开始测试时提前解除冷却。定时检测开启时，通过会解除该路由的糖果题冷却，答错按配置重新计算冷却；网络失败单独短暂退避，不延长或清除已有答错冷却。不会解除普通模型或缓存健康限制。定时检测关闭时，手动测试仅保存结果，不自动冷却，也不启动定时任务。

填写客户端使用的文本模型 ID、检测间隔（1–1440 分钟）、失败冷却时长（1–43200 分钟）。默认间隔 5 分钟、冷却 10 分钟。Chat / Responses 可以选择推理强度；不支持该参数的模型选择“上游默认”。Anthropic 使用上游默认推理设置。

后台仍为每条启用路由独立维护状态与冷却，但同源请求会复用共享观察结果。共享键由实际源站、API key 的 SHA-256、协议、最终模型、推理强度、固定题版本及请求体、有效请求头、User-Agent 和代理组成；网关组/路由 ID、检测周期与冷却不参与匹配。不同凭据、模型、协议、推理强度或会改变响应的请求参数不会共享。共享结果按每个消费者自己的检测周期计算 freshness，过期后重新请求；复用不会刷新源观察时间或延长错误冷却。路由冷却仍按各自组的策略独立计算。

检测统一发送 `stream: true`，与正常流式业务使用同一请求构造逻辑，避免部分上游对同步请求施加额外字符限制而返回 413。支持 Chat / Responses / Anthropic SSE，并兼容仍返回完整 JSON 的上游；Chat 的 `finish_reason` 后继续接收尾部 usage，直到 `[DONE]` 或 EOF；Anthropic/Responses 收到各自终态后结束读取。最早的 usage 或 `usage: null` 不作为结束标记。仍须取得完整最终答案，流式截断、错误事件、仅有 `[DONE]` 或生成长度耗尽不能判为通过。

检测题目及标准答案参考 [ranxi2001/sub2api](https://github.com/ranxi2001/sub2api) 的账号智商测试：

- `frontend/src/utils/intelligenceTest.ts` 的 `CANDY_PROMPT`。
- `backend/internal/service/pelican_scheduled.go` 的 `CandyPrompt`。
- `backend/internal/service/candy_answer.go` 的最终答案判定约定。

采用相同的糖果数量、可通过触摸区分形状的前提，要求只输出最终整数。标准答案为 `21`；检查完整的最终回答，不在推理过程、错误消息或原始 JSON 中搜索数字。`121`、`21 或 22`、`21.0`、不完整响应均不会判为通过。支持 Chat、Responses、Anthropic JSON 和 SSE；忽略推理内容，并避免重复拼接 SSE 增量与最终答案。

## 冷却范围与恢复

开启定时检测时，答题未通过或完整响应中的空答会使该渠道路由在**当前网关组内的全部模型**冷却；同一渠道在其他网关组的路由不受影响。普通模型冷却和糖果题冷却分别保存，普通连通性探测、业务请求成功与应急放行不能解除答错冷却。所有普通及保底路由都被答错冷却时，仍可能暂无可用渠道。

上游错误、响应异常或 90 秒超时不证明答错：连续检测异常分别退避 15、30、60 秒（上限 60 秒），到期复测。保留此前仍有效的答错冷却，不清除、不延长。全部合格候选仅被网络退避/普通健康限制排除时，现有应急恢复最多选两条独立来源做业务尝试；答错、人工禁用、倍率超限、模型限制仍不可绕过。升级前因网络错误留下的旧冷却会自然到期，不批量清除线上状态。

其中 HTTP 400 / 404 / 405 / 413 / 415 / 422 作为固定检测请求的参数、接口或模型兼容性错误：保留异常记录，但不新增路由退避，不按 15 秒循环重试，改为等待配置的检测间隔（若已有更晚的答错冷却则等待其到期）。这不会清除或延长此前真实答错的冷却。401 / 403、408、429、5xx 及网络异常仍走短暂退避。HTTP 错误详情展示状态码和有限长度的结构化上游说明；已知密钥和自定义请求头值脱敏，不直接保存 HTML 错误页面。

冷却到期后恢复参与调度；下次检测时间为检测间隔与冷却结束时间中较晚的一项，避免冷却中反复请求并延长限制。渠道路由行显示检测模型、最终回答、失败原因、耗时、检测时间、下次检测与冷却时间。点击“解除检测冷却”立即放行，并至少等待一个完整检测周期再测。修改检测配置、模型映射或上游凭据会使旧结果失效；执行中的旧检测不能覆盖新配置或人工解除。

每个实例的手动与定时检测合计最多并行两条路由，同时遵守上游并发限制。每 10 秒扫描到期任务；route 租约保护本路由状态，共享源租约把跨路由、跨实例的相同请求合并为一次真实 HTTP，其他消费者等待后记录复用。手动检测跳过已经完成的旧共享结果，但会合并正在进行的同源请求。共享状态独立持久化，重启后保留，不依赖事件列表；配置变更、取消和过期租约通过 fencing 阻止旧 worker 写回。检测生成上限为 4096 Token，响应捕获上限为 2 MiB，只保留最终回答前 512 个字符。

检测会产生上游费用，但不计入客户使用量、缓存健康统计或业务首字性能样本。渠道繁忙时延后检测，不因本地排队判为失败。一个固定题目的通过/失败是可重复观察的质量信号，不能证明模型身份或保证每次请求的推理质量。

## API

组创建/更新接口新增 `candy_check_enabled`、`candy_check_model`、`candy_check_interval_minutes`、`candy_check_cooldown_minutes`、`candy_check_reasoning_effort`。推理强度取 `default`、`low`、`medium`、`high`。

路由列表的 `candy_check` 返回最近状态；`active=false` 表示当前配置已不再使用该历史结果。`GET /api/gateway/groups/:id/candy-checks` 提供轻量状态刷新，不向上游发请求。`POST /api/gateway/routes/:id/candy-check/clear` 仅解除该路由的糖果题限制，不改变其他冷却。

`GET /api/gateway/routes/:id/candy-check/history` 返回该路由最近 100 条检测/人工解除事件，渠道行的「检测与解除历史」可查看。历史按 90 天保留，不再按每 route 100 条删除；列表 limit 不影响共享缓存。历史与当前检测状态分开保存，编辑检测配置不会清除历史；删除路由时一起清理。

状态及历史包含 `reused`、`source_route_id`、`source_request_id`、`observed_at`。`checked_at` 是当前 route 应用/复用结果的时间，`observed_at` 是真实源请求完成观察的时间；freshness、下次检测和答错冷却从 `observed_at` 计算。`source_request_id` 关联真实上游审计；复用不生成新的 HTTP、审计请求或客户扣费。仅完整判定的 correct/incorrect 可按组周期复用；transport/error 仅短暂抑制同源重试 15 秒，始终保持 error 语义。

`POST /api/gateway/routes/:id/candy-check/run` 立即执行该路由的手动检测，成功执行后返回 `{ "result": ... }`，答错和上游错误通过结果中的 `status` / `reason` 表达；重复检测、检测并发已满或检测期间配置被变更返回 HTTP 409。接口使用已保存的检测模型与路由配置，无需请求体。
