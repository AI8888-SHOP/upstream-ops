# 不降智检测（糖果题）

入口：网关 → 选择组 → 编辑组 → 不降智检测（糖果题）。默认关闭。

填写客户端使用的文本模型 ID、检测间隔（1–1440 分钟）、失败冷却时长（1–43200 分钟）。默认间隔 5 分钟、冷却 10 分钟。Chat / Responses 可以选择推理强度；不支持该参数的模型选择“上游默认”。Anthropic 使用上游默认推理设置。

后台对当前组每条启用的渠道路由单独检测，使用该路由自己的协议、上游密钥、代理、User-Agent 和映射后的模型。遵守路由与直连渠道的支持模型限制；不支持该检测模型或尚未确保上游密钥时跳过，并在渠道路由详情中说明原因，不会借另一条路由答对来掩盖失败。

检测题目及标准答案参考 [ranxi2001/sub2api](https://github.com/ranxi2001/sub2api) 的账号智商测试：

- `frontend/src/utils/intelligenceTest.ts` 的 `CANDY_PROMPT`。
- `backend/internal/service/pelican_scheduled.go` 的 `CandyPrompt`。
- `backend/internal/service/candy_answer.go` 的最终答案判定约定。

采用相同的糖果数量、可通过触摸区分形状的前提，要求只输出最终整数。标准答案为 `21`；检查完整的最终回答，不在推理过程、错误消息或原始 JSON 中搜索数字。`121`、`21 或 22`、`21.0`、不完整响应均不会判为通过。支持 Chat、Responses、Anthropic JSON 和 SSE；忽略推理内容，并避免重复拼接 SSE 增量与最终答案。

## 冷却范围与恢复

答题未通过、空答、上游错误、响应异常或 90 秒超时，都会使该渠道路由在**当前网关组内的全部模型**冷却；同一渠道在其他网关组的路由不受影响。普通模型冷却和糖果题冷却分别保存，普通连通性探测、业务请求成功与全部渠道受限时的应急放行都不能解除糖果题冷却。全部路由都被此检测冷却时，请求可能返回暂无可用渠道。

冷却到期后恢复参与调度；下次检测时间为检测间隔与冷却结束时间中较晚的一项，避免冷却中反复请求并延长限制。渠道路由行显示检测模型、最终回答、失败原因、耗时、检测时间、下次检测与冷却时间。点击“解除检测冷却”立即放行，并至少等待一个完整检测周期再测。修改检测配置、模型映射或上游凭据会使旧结果失效；执行中的旧检测不能覆盖新配置或人工解除。

后台最多并行检测两条路由，同时遵守上游并发限制。每 10 秒扫描到期任务；本地重叠任务和多实例重复任务分别由互斥与数据库租约防止。状态写入 PostgreSQL，重启后保留；删除路由时删除相应状态。检测生成上限为 4096 Token，响应捕获上限为 2 MiB，只保留最终回答前 512 个字符。

检测会产生上游费用，但不计入客户使用量、缓存健康统计或业务首字性能样本。渠道繁忙时延后检测，不因本地排队判为失败。一个固定题目的通过/失败是可重复观察的质量信号，不能证明模型身份或保证每次请求的推理质量。

## API

组创建/更新接口新增 `candy_check_enabled`、`candy_check_model`、`candy_check_interval_minutes`、`candy_check_cooldown_minutes`、`candy_check_reasoning_effort`。推理强度取 `default`、`low`、`medium`、`high`。

路由列表的 `candy_check` 返回最近状态；`active=false` 表示当前配置已不再使用该历史结果。`GET /api/gateway/groups/:id/candy-checks` 提供轻量状态刷新，不向上游发请求。`POST /api/gateway/routes/:id/candy-check/clear` 仅解除该路由的糖果题限制，不改变其他冷却。
